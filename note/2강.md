# 2강 (v2) — 리플렉션으로 빈 자동 생성

> 목표: 1강의 `switch` 하드코딩을 제거. `@Component` 스캔 + 리플렉션으로 빈 자동 생성·주입.
> 통과할 테스트: t1~t6 (하드코딩 없이)
> 구조 변화: `ApplicationContext`가 `com.ll.framework.ioc`로 이동, 생성자 `(basePackage)` + `init()`.
> 라이브러리: `org.reflections:reflections:0.10.2` (+ logback).

## 핵심 개념: @Component 메타 애노테이션
- `@Service`, `@Repository`, `@Configuration`은 모두 위에 `@Component`가 붙어있음(메타 애노테이션).
- `@Retention(RUNTIME)` 덕분에 실행 중에도 애노테이션 정보가 살아있어 리플렉션으로 읽을 수 있음.
- `reflections.getTypesAnnotatedWith(Component.class)`가 메타까지 펼쳐서 @Service/@Repository 클래스를 전부 찾아냄.

## 빈 이름 규칙
- 클래스명 첫 글자를 소문자로: `TestPostService` → `testPostService` (`Ut.str.lcfirst`).

## 사이클 1 — 스캔 + 리플렉션 생성 (t4)

### 🧠 머릿속 그림
`init()`: 패키지를 스캔 → "이름 → 클래스" 지도(`beanClasses`)를 그림 (아직 객체는 안 만듦).
`genBean()`: 창고 확인(싱글톤) → 없으면 `beanClasses`에서 **클래스(설계도)** 를 찾아 `newInstance()`로 객체를 찍어냄.
1강과 차이: 이름 → **클래스** → 객체 (2단 변환). switch 없음.

### 코드 핵심
```java
// init()
Reflections reflections = new Reflections(basePackage);
Set<Class<?>> componentClasses = reflections.getTypesAnnotatedWith(Component.class);
for (Class<?> cls : componentClasses) {
    if (cls.isInterface() || cls.isAnnotation()) continue; // 애노테이션 자신 제외
    beanClasses.put(Ut.str.lcfirst(cls.getSimpleName()), cls);
}
// genBean()
Class<?> cls = beanClasses.get(beanName);
Object bean = cls.getConstructors()[0].newInstance(); // 아직 인자 없이 → t4(무인자 빈)만 가능
```

### 🔍 디버깅 정리 — 스캔 결과 (실제 출력)
```
getTypesAnnotatedWith(Component) 원본 = [interface Service, interface Repository, interface Configuration,
                                         class TestPostService, class TestFacadePostService, class TestPostRepository]
등록된 빈 이름 = [testFacadePostService, testPostService, testPostRepository]
```
- 애노테이션(Service 등)은 interface로 잡혀 `isAnnotation/isInterface`로 걸러짐.
- 최종 3개 빈 등록 = 1강 switch case 3개를 스캔 한 방으로 대체.

### 🔍 디버깅 정리 — genBean("testPostRepository") 값 흐름 (실제 출력)
```
beanName = "testPostRepository"
beans.containsKey -> false
beanClasses.get(...) -> class TestPostRepository   (객체 아님, 설계도)
getConstructors() 개수 = 1, [0] = public TestPostRepository()
newInstance() -> TestPostRepository@cf65451        (여기서 진짜 객체 생성)
beans.put 후 창고 = [testPostRepository]
```
핵심: `beanClasses.get`은 **클래스(설계도)**, `newInstance`가 **객체**를 만든다.

## 사이클 2 — 생성자 파라미터 자동 주입 (t1~t6 완성)

### 🧠 머릿속 그림
생성자 = **주문서**. 리플렉션으로 생성자 파라미터를 읽어, 각 재료를 `genBean`으로 재귀 조달 → `newInstance(args)`로 생성.
1강 사이클3의 재귀 주입과 결과는 동일, 방법만 다름(손코딩 → 리플렉션 자동).

### 코드 (genBean try 블록만 변경 + import 2개)
```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Parameter;
// ...
Constructor<?> constructor = cls.getConstructors()[0];
Parameter[] parameters = constructor.getParameters();
Object[] args = new Object[parameters.length];
for (int i = 0; i < parameters.length; i++) {
    String dependencyName = Ut.str.lcfirst(parameters[i].getType().getSimpleName());
    args[i] = genBean(dependencyName);           // 재귀 조달
}
Object bean = constructor.newInstance(args);
```
- 파라미터 0개면 args 빈 배열 → `newInstance()`와 동일(하위 호환, testPostRepository OK).
- 파라미터 타입 → lcfirst → 빈 이름 (init 등록 규칙과 동일해서 정확히 매칭).

### 🔍 디버깅 정리 — genBean("testFacadePostService") 재귀 주입 (실제 출력)
```
facade 생성 시작, 파라미터 2개
  param[0] TestPostService   -> "testPostService" 재귀
    service 생성 시작, 파라미터 1개
      param[0] TestPostRepository -> "testPostRepository" 재귀
        repo 생성 시작, 파라미터 0개 -> 생성 @19b30c92
    service 완성 @4816c290 (repo 품음)
  param[1] TestPostRepository -> "testPostRepository" -> 창고에 있음, 재사용 ★
facade 완성 @4940809c
```
★ facade의 두 번째 재료 repo는 service 만들 때 이미 생성·저장돼 재사용됨.
→ facade.repo == service가 품은 repo == @19b30c92 하나 → t6 통과.
1강 사이클3과 글자 그대로 같은 결과, 방법만 리플렉션 자동화.

## 🎉 2강 완주 (t1~t6 전체 통과, 하드코딩 없음)

### 배운 것
- **애노테이션 + 메타 애노테이션**: @Service 등이 @Component를 품어, @Component 스캔 하나로 전부 잡힘. `@Retention(RUNTIME)` 필수.
- **컴포넌트 스캔**: `Reflections.getTypesAnnotatedWith(Component.class)`로 클래스 자동 수집.
- **리플렉션 생성/주입**: 이름 → 클래스(beanClasses) → `getConstructors()[0]` → `getParameters()` → 각 타입을 재귀 genBean으로 조달 → `newInstance(args)`.

### 1강 → 2강 핵심 변화
| | 1강 | 2강 |
|---|---|---|
| 빈 등록 | switch case 손코딩 | @Component 스캔 자동 |
| 이름→객체 | 직접 new | 이름→클래스→newInstance |
| DI | 손으로 genBean 호출 | getParameters로 읽어 자동 재귀 |

### 2강의 한계 → 3강 예고
지금은 `@Component`가 붙은 **클래스**만 빈이 됨.
3강: `@Configuration` 클래스 안의 `@Bean` **메서드**가 반환하는 객체도 빈으로 등록 (외부 라이브러리 객체 조립, 예: Jackson ObjectMapper). 메서드 파라미터 주입까지.
