# 확장 학습 커리큘럼 — 리플렉션 · IoC · DI 심화 로드맵

> 현재까지: 1~3강 완주 (하드코딩 → 리플렉션 스캔 → @Bean 메서드). t1~t8 통과.
> 이 문서는 **우리가 만든 컨테이너를 계속 키우면서** 리플렉션/IoC/DI 분야 전체를 난이도·흐름 순으로 배우는 계획표다.
> 진행 방식은 [CLAUDE.md](../CLAUDE.md)의 학습 규칙을 그대로 따른다 (시각화→설명→타이핑→디버깅, note 기록, 강별 push).

---

## 메인 트랙 — 컨테이너를 진짜 스프링처럼 (4강~15강)

각 강 = 기능 하나 = 개념 하나. 앞 강이 뒤 강의 토대가 되도록 난이도순으로 배치.

| 강 | 주제 | 배우는 핵심 개념 (리플렉션·IoC·DI) | 우리 컨테이너 구현 과제 | 난이도 | 선행 |
|---|---|---|---|---|---|
| **4강** | 필드 주입 | 필드 리플렉션 `getDeclaredFields`, `setAccessible`, `Field.set` | `@Autowired` 필드에 값 주입 (생성자 없이도 DI) | ★★ | 3강 |
| **5강** | 빈 이름 직접 지정 | 애노테이션 **속성값** 읽기 `annotation.value()` | `@Component("name")`, `@Bean` 이름 커스터마이즈 | ★★ | 4강 |
| **6강** | 같은 타입 여러 빈 | 후보 목록 관리, 우선순위 규칙 | `@Qualifier`, `@Primary`로 주입 대상 선택 | ★★★ | 5강 |
| **7강** | 컬렉션 주입 | 타입으로 전체 조회, 제네릭 타입 `getGenericParameterType` | `List<Handler>`, `Map<String,Handler>` 통째 주입 | ★★★ | 6강 |
| **8강** | 빈 스코프 | 싱글톤 vs 프로토타입, 생성 시점 제어 | `@Scope("prototype")` — 요청마다 새 객체 | ★★★ | 6강 |
| **9강** | 생명주기 콜백 | 메서드 리플렉션으로 후킹, 초기화/소멸 순서 | `@PostConstruct` / `@PreDestroy` 호출 | ★★★ | 4강 |
| **10강** | 순환 의존성 감지 | 생성 스택 추적, 그래프 사이클 탐지 | A→B→A 감지 후 명확한 예외 메시지 | ★★★★ | 7강 |
| **11강** | 지연 초기화 + 프록시 | **JDK 동적 프록시** `Proxy.newProxyInstance`, `InvocationHandler` | `@Lazy` — 진짜 객체를 감싼 프록시로 지연 생성 | ★★★★ | 9강 |
| **12강** | 조건부 빈 | 환경/조건 평가, 등록 필터링 | `@Conditional`, 프로파일별 빈 등록 | ★★★★ | 5강 |
| **13강** | 빈 후처리기 | 생성 파이프라인에 훅 삽입 | `BeanPostProcessor` — 초기화 전후 가로채기 | ★★★★ | 9강 |
| **14강** | AOP 기초 | 프록시 + 어드바이스 + 포인트컷 | `@Transactional` 흉내: 메서드 앞뒤에 로직 삽입 | ★★★★★ | 11·13강 |
| **15강** | 자동설정 원리 | 스타터 메커니즘, 조건부 자동 등록 | 스프링부트 `@EnableAutoConfiguration` 미니 구현 | ★★★★★ | 12·14강 |

## 기반 이론 트랙 (병렬 심화) — 필요할 때 곁들여 파기

메인 트랙을 진행하다 막히거나 더 깊이 알고 싶을 때 참고하는 이론 심화. 난이도순.

### 리플렉션(Reflection) 깊이
| # | 주제 | 내용 | 난이도 |
|---|---|---|---|
| R1 | `Class` 메타데이터 | `.class` / `getClass()` / `Class.forName`, 이름·패키지·상위타입 | ★ |
| R2 | 생성자·메서드 | `getConstructors/getMethods`, `newInstance/invoke` (이미 사용) | ★★ |
| R3 | 필드 접근 | `getDeclaredFields`, `setAccessible`, private 우회 | ★★ |
| R4 | 파라미터·`-parameters` | `Parameter.getName/getType` (이미 사용), 왜 이름이 사라지나 | ★★ |
| R5 | 애노테이션 심화 | `getAnnotation`, 속성값, 메타·합성 애노테이션 | ★★★ |
| R6 | 제네릭 타입 시스템 | `Type`, `ParameterizedType`, 소거(erasure)와 우회 | ★★★★ |
| R7 | `MethodHandles`/`VarHandle` | 리플렉션의 고속 대안, 불변성 | ★★★★ |
| R8 | 동적 프록시·바이트코드 | JDK Proxy → CGLIB/ByteBuddy, ASM 개요 | ★★★★★ |

### IoC / DI 개념 정리
| # | 주제 | 내용 | 난이도 |
|---|---|---|---|
| D1 | IoC vs DI | 제어의 역전, 의존성 주입의 3가지 방식(생성자/필드/세터) | ★ |
| D2 | 컨테이너의 책임 | 등록·해석·생성·주입·생명주기 | ★★ |
| D3 | 결합도와 테스트 | DI가 왜 테스트를 쉽게 하나, Mock 주입 | ★★ |
| D4 | 스코프와 생명주기 | 싱글톤/프로토타입/웹 스코프 | ★★★ |
| D5 | 순환 의존성 | 왜 생기나, 생성자 vs 세터 해결 | ★★★★ |
| D6 | 실제 스프링과 비교 | `ApplicationContext` 계층, `BeanFactory`, 실물 소스 읽기 | ★★★★ |

## 애노테이션 & 메타프로그래밍 (심화 곁가지)
| # | 주제 | 내용 | 난이도 |
|---|---|---|---|
| M1 | 애노테이션 정의 | `@Target`/`@Retention` (이미 사용) | ★★ |
| M2 | 런타임 vs 컴파일타임 | 리플렉션(런타임) ↔ APT(컴파일타임) | ★★★ |
| M3 | 애노테이션 프로세서(APT) | Lombok이 `@RequiredArgsConstructor`를 만드는 원리 | ★★★★ |
| M4 | 커스텀 애노테이션 기능화 | `@Transactional` 같은 선언적 기능 설계 | ★★★★ |

## 추천 학습 흐름 (한눈에)

```
[완료] 1강 하드코딩 → 2강 리플렉션 스캔 → 3강 @Bean 메서드
                                   │
          ┌────────────────────────┼────────────────────────┐
   4·5강 리플렉션 확장       6·7강 다형성 주입        8·9강 빈 관리
   (필드/애노값)           (@Qualifier/컬렉션)      (스코프/생명주기)
          └────────────────────────┼────────────────────────┘
                              10강 순환 의존성
                                   │
                     11강 프록시 도입 (@Lazy)
                                   │
              12·13강 조건부 빈 / 후처리기
                                   │
                      14강 AOP (@Transactional)
                                   │
                    15강 자동설정 (스프링부트 원리)
                                   │
                    [졸업] 실제 스프링 소스와 비교
```

## 마일스톤
- **4~7강 완료**: "웬만한 DI는 다 되는 컨테이너" — 실무 스프링 사용감의 80% 재현
- **8~10강 완료**: "빈 생명주기와 그래프를 관리하는 컨테이너"
- **11~13강 완료**: "프록시와 확장점을 가진 컨테이너" — AOP 진입 준비 완료
- **14~15강 완료**: "미니 스프링 부트" — 선언적 트랜잭션과 자동설정까지

> 한 번에 다 하지 말 것. 메인 트랙 한 강씩, 막히는 개념이 나오면 그때 기반 트랙(R/D/M)에서 해당 항목만 곁들여 판다.
