# 3강 (v3) — @Configuration + @Bean 메서드

> 목표: `@Component`를 붙일 수 없는 외부 라이브러리 객체(예: Jackson ObjectMapper)를 `@Bean` 메서드로 빈 등록.
> 통과할 테스트: 기존 t1~t6 + 신규 t7·t8.
> 스타터 구성(직접 세팅): `@Bean` 애노테이션(@Target METHOD), `TestJacksonConfig`(@Configuration + @Bean 2개), 테스트 t7·t8, build.gradle에 jackson + `-parameters`.

## 핵심 개념
- `@Component`는 **내 클래스**에만 붙일 수 있음. 남의 라이브러리 클래스(ObjectMapper 등)는 불가.
- 해결: `@Configuration` 클래스 안 `@Bean` **메서드**의 반환값을 빈으로 등록.
- 빈 만드는 길이 두 갈래: (A) @Bean 메서드 invoke, (B) @Component 생성자 newInstance. 저장·재사용은 공통.
- `-parameters` 컴파일 옵션: @Bean 메서드 파라미터 **이름**을 리플렉션으로 읽기 위함(3강 사이클2에서 사용).

## 사이클 1 — @Bean 스캔 + 무인자 메서드 (t7)

### 🧠 머릿속 그림
`init()`: @Component 스캔에 더해 @Configuration 클래스의 @Bean 메서드를 `beanMethods`(이름→Method)에 등록.
`genBean()`: 이름이 beanMethods에 있으면 → 설정 객체를 genBean으로 조달 → `method.invoke(configInstance)` → 반환값이 빈.
없으면 → 2강의 생성자 방식(else 갈래).

### 코드 핵심 (genBean 구조 변화)
```java
// init 추가
for (Class<?> configClass : reflections.getTypesAnnotatedWith(Configuration.class)) {
    for (Method method : configClass.getMethods()) {
        if (method.isAnnotationPresent(Bean.class)) {
            beanMethods.put(method.getName(), method); // 빈 이름 = 메서드 이름
        }
    }
}
// genBean: try 안에서 두 갈래 분기, put+return 공통
if (beanMethods.containsKey(beanName)) {
    Method method = beanMethods.get(beanName);
    Object configInstance = genBean(Ut.str.lcfirst(method.getDeclaringClass().getSimpleName()));
    bean = method.invoke(configInstance);   // 사이클1: 인자 없이
} else {
    /* 2강 생성자 방식 */
}
```
- 설정 클래스(TestJacksonConfig)도 @Configuration=@Component라 beanClasses에 등록됨 → genBean으로 생성 가능.
- 빈 이름 = 메서드명 (이미 camelCase라 lcfirst 불필요).

### 🔍 디버깅 정리 — genBean("testBaseJavaTimeModule") (실제 출력)
```
[BEAN-METHOD] 등록: testBaseJavaTimeModule (선언 클래스=TestJacksonConfig)
beanMethods.containsKey -> true (갈래 A)
설정 인스턴스 = TestJacksonConfig @61d9efe0   (genBean으로 조달)
메서드 파라미터 개수 = 0
method.invoke(configInstance) -> JavaTimeModule @21ca139c   (반환값 = 빈)
```
핵심: 2강 newInstance(생성자 실행) ↔ 3강 invoke(메서드 실행). 둘 다 리플렉션으로 코드 대신 실행.
